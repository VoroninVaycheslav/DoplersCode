# Одно упругое столкновение нейтрона с U‑238

Модуль Fortran читает оценённые данные **ENDF/B‑VII.1**, выбирает угол
упругого рассеяния и возвращает согласованные конечную энергию и направление
нейтрона в лабораторной системе. Ядро до столкновения неподвижно.

Поддерживаемая начальная энергия: **150 кэВ–19 МэВ**, включая границы.
Это модуль столкновения **при условии, что выбрана упругая реакция MT=2**.
Он не моделирует выбор между рассеянием, захватом, делением и другими реакциями.

## Сборка и запуск

Нужен GNU Fortran с поддержкой Fortran 2008 и `make`; для проверок — Python 3
без сторонних пакетов. В подготовленной облачной среде:

```sh
cd /workspace/DoplersCode
export PATH="/workspace/.local/bin:$PATH"
make
make test
```

На другой машине, где `gfortran` уже установлен, достаточно `make`.
Можно явно задать компилятор: `make FC=/path/to/gfortran`.

Одно столкновение при начальной энергии 1 МэВ:

```sh
./build/scatter_demo 1000000
```

10000 **независимых столкновений с одной начальной энергией**, а не цепочка:

```sh
./build/scatter_demo 1000000 10000 12345 data/u238 > build/collisions.csv
```

Аргументы: `E_in_eV`, число столкновений, seed, каталог данных.
По умолчанию: `1000000 1 12345 data/u238`.
Входное направление демонстрации — `(0,0,1)`.

В начале вывода находятся строки комментариев `#` с сечениями и параметрами,
затем CSV:

```text
E_out_eV,omega_x,omega_y,omega_z,mu_cm
```

`mu_cm` — косинус угла в центре масс. В демонстрации `omega_z` равен косинусу
лабораторного угла; в общем случае это скалярное произведение входного и
выходного направлений. Угол в радианах: `acos(mu)`.
Одинаковый seed воспроизводит выборку в одной реализации компилятора/RNG;
побитовая воспроизводимость между разными компиляторами не обещается.

## Какие данные сохранены

В `data/u238/` лежат неизменённые строки отдельных разделов ENDF:

| Файл | Раздел | Содержание |
|---|---|---|
| `total.endf` | MF=3, MT=1 | Полное микроскопическое сечение всех реакций |
| `elastic.endf` | MF=3, MT=2 | Интегральное упругое сечение |
| `angular.endf` | MF=4, MT=2 | Коэффициенты Лежандра углового распределения в центре масс |
| `evaluation_header.endf` | MF=1, MT=451 | Описание оценки, авторы, ссылки |
| `provenance.json` | — | URL, закреплённый Git commit, SHA‑256, единицы и область применимости |

Источник: [пример U‑238 в NJOY/ENDFtk](https://github.com/njoy/ENDFtk/blob/6596073f17b21952407f6f16b5b812ca3b4a8d67/python/examples/resources/n-U238.endf).
Заголовок самого файла идентифицирует библиотеку как **ENDF/B‑VII.1**, MAT=9237,
ZA=92238. Это данные из семейства ENDF/B; они не обозначаются как VIII.0 или
выгрузка из JANIS. Исходный архив IAEA оказался недоступен через сетевую
политику среды, поэтому использован доступный закреплённый источник NJOY.
Уведомление об условиях распространения репозитория-источника сохранено в
`data/u238/SOURCE_LICENSE.txt`.

В этой оценке дифференциальное сечение представлено **сечением MT=2 и
коэффициентами MF=4**, а не отдельной сеткой значений по углам. Это позволяет
восстановить его без дополнительной дискретизации:

\[
p(\mu_c\mid E)=\frac12\left[1+\sum_{\ell=1}^{L}(2\ell+1)a_\ell(E)P_\ell(\mu_c)\right],
\qquad
\frac{d\sigma_{el}}{d\Omega_c}=\frac{\sigma_{el}(E)}{2\pi}p(\mu_c\mid E).
\]

`data%differential_cross_section(E,mu_cm)` возвращает именно это
дифференциальное сечение в **барн/ср в системе центра масс**.
Полное сечение MT=1 нельзя подставлять вместо упругого MT=2 в эту формулу.

Единицы входной/выходной энергии — **эВ**, сечений — **барн**.
Направление — безразмерный единичный вектор. Отношение масс берётся из файла:
`AWR=236.0058`, то есть масса ядра относительно массы нейтрона,
а не целое массовое число 238.

Исходные разделы содержат более широкий энергетический диапазон, чем разрешает
модуль. Ниже 149.0288 кэВ в исходной оценке присутствует резонансная область;
данный проект не реализует её обработку и температурную подготовку данных.
При 20 МэВ и выше угловой полином этой оценки местами отрицателен
(при 20 МэВ минимум около `-0.000699`). Поэтому выбрана верхняя граница 19 МэВ.
Отрицательные плотности не обрезаются и не перенормируются. Проверка на Python
сертифицирует неотрицательность полиномов всех узлов используемого диапазона
точной рациональной арифметикой и разбиением в базисе Бернштейна. Линейная
интерполяция между положительными плотностями сохраняет неотрицательность.

## Как происходит одно столкновение

1. Прочитать и проверить MF=3 и MF=4: изотоп, систему отсчёта, порядок,
   интерполяцию и сетки. Файлы читаются один раз при `load`.
2. Линейно интерполировать сечения и коэффициенты Лежандра по энергии:
   это закон `INT=2` из этих разделов ENDF. Недостающие старшие коэффициенты
   в соседнем узле считаются нулевыми.
3. Выбрать `u1,u2` равномерно на `[0,1)`.
4. Найти `mu_cm` из `F(mu_cm)=u1` бисекцией (50 итераций). Интеграл полинома
   вычисляется аналитически:

\[
F(\mu)=\frac{\mu+1}{2}
+\frac12\sum_{\ell=1}^{L}a_\ell
\left[P_{\ell+1}(\mu)-P_{\ell-1}(\mu)\right].
\]

5. Выбрать азимут `phi=2*pi*u2`. Рассчитать из того же `mu_cm`:

\[
\frac{E_{out}}{E_{in}}=
\frac{A^2+1+2A\mu_c}{(A+1)^2},
\qquad
\mu_{lab}=\frac{1+A\mu_c}{\sqrt{A^2+1+2A\mu_c}}.
\]

6. Построить ортонормированный базис относительно **входного направления**
   и повернуть вектор на лабораторный угол и азимут.

Энергия не генерируется независимо от угла: её распределение уже следует из
углового закона и кинематики. Векторный поворот работает для любого входного
единичного направления, включая оба полюса.

## Использование модуля в своём коде

```fortran
use neutron_collision, only: collision_data, dp
implicit none
type(collision_data) :: uranium
real(dp) :: e_out, omega_out(3), mu_cm, sigma_t, sigma_el, dsdo

call uranium%load('data/u238')
call uranium%cross_sections(1.0e6_dp, sigma_t, sigma_el)
dsdo = uranium%differential_cross_section(1.0e6_dp, 0.5_dp)

call uranium%scatter( &
    energy_in    = 1.0e6_dp, &
    direction_in = [0.0_dp, 0.0_dp, 1.0_dp], &
    energy_out   = e_out, &
    direction_out= omega_out, &
    mu_cm        = mu_cm)
```

При необходимости передай в `scatter` необязательный аргумент
`uniforms=[u1,u2]`, чтобы использовать собственный генератор случайных чисел.
Без него вызывается стандартный `random_number` Fortran. `mu_cm` тоже
необязателен. Входные и выходные переменные должны быть разными: не передавай
одну переменную одновременно как `energy_in` и `energy_out` либо как оба
направления. Для цепочки столкновений присваивай выход входу после вызова.

Загрузка/вызов с неподдерживаемой энергией, неправильным форматом,
неединичным направлением или неверными случайными числами завершается
с понятным сообщением и ненулевым кодом. Это намеренно простой интерфейс:
для встраивания в большую программу обработку ошибок можно впоследствии
заменить на возвращаемый статус.

Для следующего этапа переноса полное сечение даст длину свободного пробега
после перехода к макроскопическому сечению, а `sigma_el/sigma_t` — вероятность
выбора упругой реакции. Сейчас оба сечения доступны, но выбор остальных
реакций и их выходные состояния ещё не реализованы.

## Проверки

`make test` проверяет:

- чтение ENDF и контрольные суммы сохранённых разделов;
- нормировку PDF, границы и монотонность CDF, первый момент и интеграл
  дифференциального сечения;
- 24000 столкновений на шести энергиях, включая интерполяционные точки,
  границы диапазона и близкие узлы около 10 МэВ;
- единичность направлений, границы энергии, связь энергии с углом,
  сохранение энергии с учётом отдачи ядра и импульса;
- независимый разбор ENDF на Python и ещё 32000 случайных столкновений:
  угловые интервалы, средние углы/энергии и равномерность азимута;
- явный отказ для недопустимых аргументов, отсутствующих и оборванных файлов.

Статистические проверки используют допуск шесть стандартных отклонений.
Они сравнивают выборку с реальными коэффициентами ENDF, а не с изотропной моделью.

При 1 МэВ из загруженных данных:

```text
sigma_total   = 7.068068 barn
sigma_elastic = 4.707573 barn
<mu_cm>       = 0.430948
```

Это нерелятивистская модель свободного неподвижного ядра. Она не включает
тепловое движение, химическую связанность, неупругие реакции или деление.
Выходная энергия одного допустимого столкновения может оказаться ниже
150 кэВ; новое столкновение с такой начальной энергией модуль уже отклонит.
Парсер предназначен для приложенной оценки, а не для произвольных ENDF-файлов:
неподдерживаемые представления MF=4 или законы интерполяции отклоняются.

## Повторная загрузка данных

Данные уже включены в проект, сеть при запуске не нужна. Для воспроизведения
выгрузки из корня проекта:

```sh
python3 tools/prepare_data.py
```

Либо из заранее полученного полного файла:

```sh
python3 tools/prepare_data.py --source /path/to/n-U238.endf
```

Перед извлечением проверяется SHA‑256 полного файла из `provenance.json`.
Источник закреплён по commit; разделы копируются без изменения строк.
